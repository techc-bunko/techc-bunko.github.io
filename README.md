# 三色文庫 — 学園祭頒布サイト

オリジナル短編小説3作を、**第一章だけ無料公開／続きはアクセスカードの合言葉で解錠**する形で
Web に置くための一式です。サーバー・課金・アカウントは一切不要（GitHub Pages で無料公開）。

---

## 1. できあがるもの

```
src/                        ← 原稿と素材（.gitignore 済み。push しない）
  config.json               サイトの文言・価格・作品のメタ情報
  works/*.json              本文（一字一句そのまま）
  assets/style.css          デザイン。ここを編集する
  assets/reader.js          リーダーの動き。ここを編集する

docs/                       ← ここを GitHub Pages で公開する（すべて生成物）
  index.html                本棚トップ（3篇を並べて紹介・読みかた・合言葉入力）
  sample/index.html         試し読み（各作の冒頭。無料配布スリップのQRの行き先）
  works/kokoro.html         心の罪（全7章）
  works/mikata.html         味方（全8話）
  works/dareka.html         誰かのために生きてきた私が、私になる日（全8章）
  assets/style.css          src/assets/style.css のコピー（手で編集しない）
  assets/reader.js          src/assets/reader.js のコピー（手で編集しない）
  assets/ogp/*.png          SNSにURLを貼ったときのサムネイル（1200×630）
  assets/icon-*.png         ホーム画面に追加したときのアイコン
  sw.js                     オフライン用 Service Worker（自動生成）
  manifest.webmanifest      ホーム画面追加用の設定（自動生成）
```

読者側の動き:

1. QR を読む → トップページ
2. 作品を開くと、扉と目次が出て、本文は「🔒 ここから先は、カードをお持ちの方へ」
   （**試し読みはトップからは辿れない**。会場で配る紙のサンプルとスリップのQRが試し読みの役目）
3. カードの合言葉を入力 → **その場で目次の鍵が全部外れる**
4. 端末に合言葉が保存されるので、**次回からは自動で開く／3作とも共通**
5. 本文は**1話ずつ**表示する。URL は `works/mikata.html#c5` のように話番号が付くので、
   途中の話をそのまま共有・再訪できる。話末の「次の話 →」か、右上の目次ボタンで移動する
6. 扉に「◯◯から読む」ボタンが出る（前回読んでいた話。位置も含めて覚えている）
7. 本文は**既定で横組み**。右上の設定から縦組み・文字サイズ・書体・明暗を変えられる

## 2. なぜ「JS でパスワード照合」ではないのか

学園祭サイトでよくある「入力値が合っていたら本文を表示する」方式は、
**ページのソースを見れば本文が全部読めてしまう**ため、カードを買う意味がなくなります。

このサイトは本文そのものを **AES-GCM 256bit で暗号化**してページに埋め込んでいます。
合言葉から PBKDF2（SHA-256, 21万回）で鍵を作り、ブラウザの中で復号します。
合言葉を知らない人には、ソースを見ても**意味のないランダムなデータしか見えません**。

> ⚠️ もちろん「買った人が合言葉を友達に教える」ことは防げません。
> そこは紙の同人誌と同じで、モラルとカードの入手体験でカバーする前提です。

## 3. 使い方

### 準備（初回のみ）

`passphrase.txt` に合言葉を1行で書きます。

> ⚠️ **この README は公開リポジトリに入っています。ここに合言葉そのものを書かないでください。**
> 現在の合言葉は `passphrase.txt`（Git 管理外）を見るか、`node tools/build.js` の出力で確認できます。

- 半角英数がおすすめです（スマホで打ちやすい）
- 次のゆらぎは**すべて無視して照合**します。会場でスマホから打つ前提のためです
  - 大文字小文字、全角半角
  - 空白
  - ハイフン類（`-` `‐` `—` など）と**長音符「ー」**（日本語キーボードだと `-` の代わりに `ー` を打つ人が多い）
  - アンダーバー `_`、中黒 `・`
- 変更したら `tools/build.js` と `docs/assets/reader.js` の `normalizePass` が
  **同じ結果を返すこと**を必ず確認してください（ずれると正しい合言葉でも解錠できません）
- このファイルは `.gitignore` 済みなので GitHub には上がりません

### ビルド

```bash
node tools/build.js
```

`src/` の原稿と設定から `docs/` を作り直します。原稿や設定を変えたら毎回これを実行してください。

### ローカルで確認

```bash
node tools/serve.js
```

→ http://localhost:8080/

> **HTML ファイルをダブルクリックで開いても動きません。**
> ブラウザの暗号 API（`crypto.subtle`）は `file://` では無効化されているためです。
> 確認は必ず上のローカルサーバーか、公開後の `https://` 経由で行ってください。

## 4. 中身を書き換える

### 文言・価格・ブース名 → `src/config.json`

| 項目 | 内容 |
|---|---|
| `siteUrl` | **公開後の URL**（例 `https://〇〇.github.io/sanshoku-bunko`）。ここが空だと OGP（SNSのサムネイル）が出ません |
| `siteName` / `tagline` | 文庫名・キャッチコピー |
| `festival.booth` / `price` | ブース名・カード1枚の価格 |
| `gate.previewChapters` | 作品ページで無料で読める章数。**現在 0**（本編は全章ロック） |
| `sample.chapters` / `sample.exclude` | 試し読みページに載せる章数（既定 1）と、載せない作品の slug |
| `sample.linkFromTop` | トップページに試し読みへのリンクを出すか。**既定は出さない**（`true` にすると出る） |
| `works[].accent` | 作品ごとのアクセント色。**地の色に対して薄すぎても構いません**。文字やボタンに使う濃さはビルド時にコントラスト比 4.5:1 を満たすまで自動で調整し、飾り（帯・罫）にだけ元の色をそのまま使います |
| `works[].tagline` / `blurb` | 帯文・あらすじ。**帯文は現在すべて空**（後で考え直す予定） |

### デザイン・リーダーの動き → `src/assets/`

- `src/assets/style.css` … 見た目。色・余白・文字組みはすべて先頭のトークン（`:root` の `--…`）で決まる
- `src/assets/reader.js` … 合言葉ゲート、1話ずつの表示、設定の保存

`docs/assets/` の同名ファイルは**ビルドが上書きするコピー**です。直接編集しても次の
`npm run build` で消えます。必ず `src/assets/` のほうを編集してください。

> `reader.js` の `normalizePass()` と `tools/build.js` の `normalizePass()` は
> **同じ結果を返さないといけません**。片方だけ変えると、正しい合言葉でも解錠できなくなります。

### 本文 → `src/works/*.json`

原稿は次の形です。`blocks` に段落を並べるだけです。

```json
{
  "slug": "work3",
  "order": 3,
  "langs": {
    "ja": {
      "title": "作品タイトル",
      "chapters": [
        {
          "id": "s1",
          "num": "第 一 章",
          "title": "章タイトル",
          "pov": "視点人物名",
          "blocks": [
            { "t": "p", "text": "本文の一段落。" },
            { "t": "break" },
            { "t": "p", "text": "場面転換のあとの段落。" }
          ]
        }
      ]
    }
  }
}
```

- `{ "t": "break" }` は場面区切り（✿ ✿ ✿）になります
- `text` の中の改行は、そのまま改行（`<br>`）として出ます
- 「」で始まる行は自動で字下げなしになります

JSON を直接いじるのは大変なので、**プレーンテキストから取り込む**こともできます。
`src/raw/*.txt` を次の書式で書いて `node tools/import.js <ファイル名> <slug>` を実行してください。

```
# 作品タイトル
## 第 一 章 | 章タイトル | 視点人物

空行で段落を区切る。
続けて書いた行は、同じ段落の中の改行になる。

***        ← この行だけで場面区切り（✿ ✿ ✿）
```

例:

```bash
node tools/import.js mikata mikata && node tools/build.js
```

原稿の置き場所:

- 心の罪 … `src/raw/kokoro.txt` が原稿（元は HTML から抽出したものを書き出したもの。`tools/extract.js` は再実行しないこと）
- 味方 … `src/raw/mikata.txt` が原稿
- 誰かのために生きてきた私が、私になる日 … `src/raw/dareka.txt` が原稿
- 文豪冷戦（現在は不採用） … `src/raw/bungo.txt`

原稿を直すときは `src/raw/*.txt` を編集 → `node tools/import.js <ファイル名> <slug>` → `node tools/build.js`。

## 5. 公開する

**設定済みです。** 公開先は <https://techc-bunko.github.io/>。

| 項目 | 値 |
|---|---|
| Organization | `techc-bunko`（所有は個人アカウント） |
| リポジトリ | `techc-bunko.github.io`（Public） |
| Pages | Deploy from a branch ／ `main` ／ `/docs` |

内容を更新したいときは、ビルドしてから push するだけです。

```bash
node tools/build.js && git add -A && git commit -m "更新" && git push
```

1〜2分で反映されます。

> **push されないもの**
> - `passphrase.txt` … 合言葉。漏れると全部無料で読めます
> - `src/` … **原稿そのもの**。公開リポジトリに平文で置くとカードを売る意味がなくなるため除外しています
>
> つまり**原稿は GitHub にバックアップされません。** `src/` は別途どこかにコピーを取ってください。

更新したら、シークレットウィンドウで開いて「第一章しか読めないこと」を毎回確認してください。

### 合言葉を変えたくなったら

`passphrase.txt` を書き換えて `node tools/build.js` → もう一度 push。
（すでにカードを配ったあとに変えると、その端末は再入力が必要になります）

## 6-2. 画面まわりの機能

読者が右上の設定ボタン（≡に丸のアイコン）から切り替えられます。
設定は端末に保存され、3篇すべてに共通で効きます。

| 項目 | 選べるもの |
|---|---|
| **明るさ** | 端末に合わせる / 明 / 暗（既定は端末に追従） |
| **文字の大きさ** | 5 段階 |
| **書体** | 明朝 / ゴシック（既定は明朝） |
| **組み方** | 横組み / 縦組み（既定は横組み。縦組みは右から左へ横スクロール） |

そのほかに入っているもの:

- **1話ずつの画面切り替え**（`#c5` のようにURLに話番号が付く）。話末に「前の話 / 目次 / 次の話」
- 右上の**目次ボタン**（読んでいる途中でも開ける。現在の話に印が付く）
- **読書進捗バー**（ヘッダーの下。縦組みでも横組みでも同じように進む）
- **読んでいた位置の記憶**。扉に「◯◯から読む」ボタンが出る。既読の話には「既読」が付く
- キーボードの **← →** で前後の話へ

> 縦組みの `scrollLeft` は、ブラウザによって「0 が先頭で左へ進むほどマイナス」と
> 「右端の値が先頭で 0 に近づくほど末尾」の2通りがあります。`reader.js` は起動時に
> どちらかを実測して判定しています（判定しないと先頭と末尾が入れ替わります）。

### オフライン対応

一度開いたページは端末に保存され、**電波が届かない会場でも読めます**（Service Worker）。
`https://` でのみ動きます。ローカル確認時に古い画面が出続けるときは、
ブラウザの開発者ツール → Application → Service Workers から Unregister してください。

### OGP画像・アイコンを作り直す

作品を足したり色を変えたりしたら、画像も作り直します。

```bash
node tools/serve.js
```

を起動した状態で <http://localhost:8080/> をブラウザで開き、開発者ツールのコンソールで:

```js
const s = document.createElement('script');
s.src = '/_make-images.js';
document.head.appendChild(s);
s.onload = () => __BUNKO_GEN.run().then(console.log);
```

`src/config.json` と `src/works/*.json` を読んで、`docs/assets/ogp/*.png` と
`docs/assets/icon-*.png` を描き直して保存します（描画のコードは `tools/make-images.js`）。
