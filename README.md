# 三色文庫 — 学園祭頒布サイト

オリジナル短編小説3作を、**第一章だけ無料公開／続きはアクセスカードの合言葉で解錠**する形で
Web に置くための一式です。サーバー・課金・アカウントは一切不要（GitHub Pages で無料公開）。

---

## 1. できあがるもの

```
docs/                       ← ここを GitHub Pages で公開する
  index.html                本棚トップ（3篇を並べて紹介・購入案内）
  works/kokoro.html         心の罪 ―― 時効（全7章）
  works/rettoukan.html      劣等感 (1)（全8話）
  assets/style.css          共通デザイン（和紙色 × 作品ごとのアクセント色）
  assets/reader.js          合言葉ゲート／縦組み／文字サイズ／夜モード／読書位置保存
  assets/ogp/*.png          SNSにURLを貼ったときのサムネイル（1200×630）
  assets/icon-*.png         ホーム画面に追加したときのアイコン
  sw.js                     オフライン用 Service Worker（自動生成）
  manifest.webmanifest      ホーム画面追加用の設定（自動生成）
```

読者側の動き:

1. QR を読む → トップページ
2. 各作品の **第一章は無料で読める**
3. 続きの手前に「🔒 ここから先は、カードをお持ちの方へ」
4. カード裏の合言葉を入力 → **その場で残り全章が現れる**
5. 端末に合言葉が保存されるので、**次回からは自動で開く／3作とも共通**

---

## 2. なぜ「JS でパスワード照合」ではないのか

学園祭サイトでよくある「入力値が合っていたら本文を表示する」方式は、
**ページのソースを見れば本文が全部読めてしまう**ため、カードを買う意味がなくなります。

このサイトは本文そのものを **AES-GCM 256bit で暗号化**してページに埋め込んでいます。
合言葉から PBKDF2（SHA-256, 21万回）で鍵を作り、ブラウザの中で復号します。
合言葉を知らない人には、ソースを見ても**意味のないランダムなデータしか見えません**。

> ⚠️ もちろん「買った人が合言葉を友達に教える」ことは防げません。
> そこは紙の同人誌と同じで、モラルとカードの入手体験でカバーする前提です。

## 3. 使い方

### 準備（初回のみ）

`passphrase.txt` に合言葉を1行で書きます（現在は `sakura2026`）。

```
sakura2026
```

- 半角英数がおすすめです（スマホで打ちやすい）
- **大文字小文字・全角半角・空白は区別しません**（`ＳＡＫＵＲＡ 2026` でも通ります）
- このファイルは `.gitignore` 済みなので GitHub には上がりません

### ビルド

```bash
node tools/build.js
```

`src/` の原稿と設定から `docs/` を作り直します。原稿や設定を変えたら毎回これを実行してください。

### ローカルで確認

```bash
node tools/serve.js
```

→ http://localhost:8080/

> **HTML ファイルをダブルクリックで開いても動きません。**
> ブラウザの暗号 API（`crypto.subtle`）は `file://` では無効化されているためです。
> 確認は必ず上のローカルサーバーか、公開後の `https://` 経由で行ってください。

## 4. 中身を書き換える

### 文言・価格・ブース名 → `src/config.json`

| 項目 | 内容 |
|---|---|
| `siteUrl` | **公開後の URL**（例 `https://〇〇.github.io/sanshoku-bunko`）。ここが空だと OGP（SNSのサムネイル）が出ません |
| `siteName` / `tagline` | 文庫名・キャッチコピー |
| `festival.booth` / `price` | ブース名・カード1枚の価格 |
| `gate.previewChapters` | 無料で読める章数（既定 1） |
| `works[].accent` | 作品ごとのアクセント色 |
| `works[].tagline` / `blurb` | 帯文・あらすじ |

### 本文 → `src/works/*.json`

原稿は次の形です。`blocks` に段落を並べるだけです。

```json
{
  "slug": "work3",
  "order": 3,
  "langs": {
    "ja": {
      "title": "作品タイトル",
      "chapters": [
        {
          "id": "s1",
          "num": "第 一 章",
          "title": "章タイトル",
          "pov": "視点人物名",
          "blocks": [
            { "t": "p", "text": "本文の一段落。" },
            { "t": "break" },
            { "t": "p", "text": "場面転換のあとの段落。" }
          ]
        }
      ]
    }
  }
}
```

- `{ "t": "break" }` は場面区切り（✿ ✿ ✿）になります
- `text` の中の改行は、そのまま改行（`<br>`）として出ます
- 「」で始まる行は自動で字下げなしになります

JSON を直接いじるのは大変なので、**プレーンテキストから取り込む**こともできます。
`src/raw/*.txt` を次の書式で書いて `node tools/import.js <ファイル名> <slug>` を実行してください。

```
# 作品タイトル
## 第 一 章 | 章タイトル | 視点人物

空行で段落を区切る。
続けて書いた行は、同じ段落の中の改行になる。

***        ← この行だけで場面区切り（✿ ✿ ✿）
```

例:

```bash
node tools/import.js bungo bungo && node tools/build.js
```

原稿の置き場所:

- 桜色メイド・心の罪 … `tools/extract.js` で元の HTML から抽出済み（再実行不要）
- 文豪冷戦 … `src/raw/bungo.txt` が原稿。直すときはこのテキストを編集 → `import.js` → `build.js`

## 5. GitHub Pages で公開する

1. GitHub で新しいリポジトリを作る（例: `sanshoku-bunko`／**Public**）
2. この `gakuensai_bunko` フォルダの中身を push する
   ```bash
   git init
   git add .
   git commit -m "三色文庫"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/sanshoku-bunko.git
   git push -u origin main
   ```
3. リポジトリの **Settings → Pages** を開く
4. **Source: Deploy from a branch** ／ **Branch: `main`** ／ **Folder: `/docs`** を選んで Save
5. 1〜2分後、`https://<ユーザー名>.github.io/sanshoku-bunko/` で公開されます

> `passphrase.txt` は `.gitignore` 済みなので push されません。
> 公開後は必ず、シークレットウィンドウで開いて「第一章しか読めないこと」を確認してください。

### 合言葉を変えたくなったら

`passphrase.txt` を書き換えて `node tools/build.js` → もう一度 push。
（すでにカードを配ったあとに変えると、その端末は再入力が必要になります）

## 6-2. 画面まわりの機能

読者が右上のボタンで切り替えられます。設定は端末に保存され、次に開いたときも維持されます。

| ボタン | 動き |
|---|---|
| **縦組 / 横組** | 本文を縦書きにする。章ごとに右から左へ横スクロールして読む形になる |
| **あ** | 文字サイズ 3 段階 |
| **自動 / 夜 / 昼** | 配色。既定は端末の設定に追従 |

そのほか、目次からの章ジャンプ、読書進捗バー、**読んでいた位置の記憶**（次に開くと続きから）が入っています。

### オフライン対応

一度開いたページは端末に保存され、**電波が届かない会場でも読めます**（Service Worker）。
`https://` でのみ動きます。ローカル確認時に古い画面が出続けるときは、
ブラウザの開発者ツール → Application → Service Workers から Unregister してください。

### OGP画像・アイコンを作り直す

作品を足したり色を変えたりしたら、画像も作り直します。

```bash
node tools/serve.js
```

を起動した状態で <http://localhost:8080/> をブラウザで開き、開発者ツールのコンソールで:

```js
const s = document.createElement('script');
s.src = '/_make-images.js';
document.head.appendChild(s);
s.onload = () => __BUNKO_GEN.run().then(console.log);
```

`src/config.json` と `src/works/*.json` を読んで、`docs/assets/ogp/*.png` と
`docs/assets/icon-*.png` を描き直して保存します（描画のコードは `tools/make-images.js`）。
