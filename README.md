# 劣等感は味方 — 1作品サイト

短編1篇を全編無料で公開する静的サイト。GitHub Pages（`docs/` 公開）で動く。
ビルドは Node のみで、依存パッケージはゼロ。

```bash
node tools/build.js   # src/ → docs/ を生成
node tools/serve.js   # http://localhost:8091 で確認（引数でポート変更可）
```

| slug | 題 | 構成 | 分量 |
|---|---|---|---|
| `rettoukan` | 劣等感は味方 | 全8話 | 約 6,029 字 |

## 構成

```
src/
  config.json        slug・アクセント色・分類・注意書き
  raw/*.txt          原稿の原本。これが唯一の正
  assets/style.css   デザイン（編集元）
  assets/reader.js   リーダー（編集元）
docs/                ビルド結果。GitHub Pages が配信する。手で編集しない
tools/build.js       ビルド
tools/serve.js       ローカル確認用サーバー
```

`docs/assets/style.css` と `docs/assets/reader.js` は `src/assets/` からのコピー。
直したいときは必ず `src/assets/` のほうを直してビルドし直すこと。

トップページ（`docs/index.html`）が扉・目次・本文を兼ねる。本文は 1 話ずつ
`#c1`, `#c2` … で切り替わり、ページ遷移は起きない。

## 原稿の扱い（重要）

- **`src/raw/*.txt` の本文は一字も書き換えない。** 誤字も句読点もそのまま出す。
- 機械で足してよいのは章の区切り（`## ` で始まる行）だけ。
  章タイトルや視点ラベルなど、書き手が書いていないものを本文側に足さない。
- `## ` の行は `## 第 一 話` のように書く。`|` で区切ると後ろが章題になる（例: `## 其 の 一 | 罪`）。
- `***` だけの行は場面転換の区切りとして扱われる。

原稿を差し替えたあとは、本文が落ちていないか照合できる。
段落数と文字数が合い、全段落が一字一句一致することを確かめること。

## 原稿の書式

```
# 作品名

## 第 一 話

一段落を一行で書く。空行は無視される。

## 第 二 話

...
```

## 別の作品でこの仕組みを使う

1. `src/raw/<新しい slug>.txt` に原稿を置く
2. `src/config.json` の `slug` と `accent`・`genre`・`unit` を書き換える
3. `node tools/build.js`

1サイト1作品の作りなので、2作目は**このフォルダごと複製**して使う。
1つのサイトに複数作品を並べたい場合は `webnovel/`（未明）のほうが向いている。

## 公開

https://techc-bunko.github.io/ で公開している。
GitHub Pages の配信元は `main` ブランチの `/docs` フォルダ。

`src/config.json` の `siteUrl` に公開URLを入れると、OGP（SNSでリンクを貼ったときの

### このリポジトリの前身について

`techc-bunko.github.io` はもともと**三色文庫**（学園祭で頒布するアクセスカード方式の
小説サイト）の公開先だった。2026-09-10 に main をこのサイトへ入れ替えている。
三色文庫は消していない。

| ブランチ | 中身 |
|---|---|
| `sanshoku-bunko` | 入れ替え直前に公開されていた三色文庫 |
| `sanshoku-bunko-wip` | その上に載っていた作りかけの変更 |

ただし三色文庫の **原稿（`src/`）・カード印刷データ（`print/`）・合言葉
（`passphrase.txt`）は当時 .gitignore されていたため、どのブランチにも無い。**
それらはローカルの `gakuensai_bunko/` フォルダにしかないので、消さないこと。

なお、このサイトは全編無料なので `src/` を公開して構わない（三色文庫と違い、
隠す必要がある本文が無い）。

## メモ

- 表示設定（明暗・文字サイズ・書体・縦横）と読みかけの位置は、読者の端末の
  localStorage にだけ入る。サーバーには何も送っていない。キーの接頭辞は `yomi.`。
  この接頭辞は `tools/build.js` の `THEME_BOOT` と `src/assets/reader.js` の両方に
  書いてあるので、変えるときは必ず両方そろえること。ずれると初回描画で
  設定が当たらず、暗い設定の人に白い画面が一瞬出る。
- Service Worker で一度開いたページはオフラインでも読める。キャッシュ名は
  `index.html`・`style.css`・`reader.js` のハッシュから作るので、どれを直しても
  版数が変わり、更新は次の訪問で自動的に入れ替わる。
  ローカルで確認するときは古いキャッシュが残ることがあるので、
  DevTools で Service Worker を unregister してから見ること。
- アクセント色はビルド時にコントラスト比 4.5:1 まで自動調整される（`--accent`）。
  飾りには調整前の色（`--accent-raw`）を使う。
  現在の設定（`#3f7f8c`）での実測は 明 4.54:1 / 暗 7.26:1。
- 縦組みは見出しと本文をまとめた面（`.chapter__stage`）ごと `vertical-rl` にして
  横スクロールさせている。この節の CSS では論理プロパティ（`margin-inline` 等）が
  縦横入れ替わるため、必ず物理プロパティで書くこと。
